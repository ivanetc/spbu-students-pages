# Brief: сдвоенная лекция по Java Collections Framework

Этап: конспект `lectures/autumn/lecture_07.md` написан, схемы визуально проверены отдельным агентом, итоговое независимое ревью закрыто без открытых замечаний. Презентация — следующий этап по готовому конспекту.

## Запрос и контекст

- Источник: `lectures/autumn/lecture_06.md`. Студентам рассказаны только разделы 1–4 (файлы и пакеты, `enum`, `record`). Разделы 5–12 о коллекциях не рассказаны; их надо учитывать как авторский материал, но не считать уже известными.
- Предыдущие знания: первые пять осенних лекций; массивы и O-нотация знакомы. Связные списки и хеширование нужно объяснять.
- После этой сдвоенной лекции курс переходит к функциональным интерфейсам, лямбдам и Stream API; затем к исключениям и вводу-выводу. Отдельной будущей лекции о коллекциях не будет.
- Длительность: 2 × 80 минут чистого времени.
- Версия для публичного API и разбора реализации: Java 21. Материал шестой лекции местами ориентирован на Java 26, поэтому сверять версионные различия.

## Цель текущего этапа

Изучить исходные конспекты и официальные учебные материалы ведущих университетов (до пяти курсов), сохранить исследования в отдельных Markdown-файлах, составить конкретный план сдвоенной лекции и сквозного примера. Показать план пользователю до написания полного конспекта; презентацию затем строить по готовому конспекту.

## Требуемый охват

- Часть I: назначение и устройство Framework, дерево интерфейсов, контракты, выбор коллекции по задаче и основные операции.
- Часть II: внутреннее устройство и доказательство временных оценок `ArrayList`, `LinkedList`, `HashMap`, `HashSet`; оценить необходимость `ArrayDeque`, сортированных коллекций и механизма обхода.
- Учесть применение: равенство и хеширование, порядок элементов, мутабельность, итерация, удаление при обходе, сортировка, границы оценок, переход к Stream API.

## Ограничения

- Не менять опубликованные лекции, навигацию и другие прежние рабочие материалы на этапе планирования.
- Не выводить формулы сложности из общих лозунгов: указывать модель стоимости, средний/амортизированный/худший случай и условия инвариантов.
- В исследовании различать API-контракт Java 21 и устройство конкретной реализации OpenJDK 21.
- Вопрос о точном объёме сортировки и `Iterator` в устной части решить в плане исходя из 160 минут и перехода к Stream API.

## Принято для проекта плана

- В первой половине `Iterator` и обход `Map` входят в устное ядро; сортировка и `Comparator` вводятся на уровне применения без лямбд.
- Во второй половине подробное доказательство стоимости даётся для `ArrayList`, `LinkedList`, `HashMap`, затем `HashSet` выводится из `HashMap`; `ArrayDeque` разбирается кратко как пятая практическая реализация.
- Результаты лежат в `author-analysis.md`, `university-research.md`, `java21-source-notes.md`, `example-contract.md`, `plan.md`.
- Остаётся согласовать, устраивает ли преподавателя такое распределение глубины и вынесение длинных справочных разделов в письменный конспект.

## Новые требования к конспекту

- Лаконичный связующий текст, заголовки, списки и таблицы; основные методы каждого семейства в первой части.
- Короткие примеры Java; условный псевдокод явно обозначать, не маскировать под запускаемый Java-код.
- Много точных схем в одном комфортном визуальном стиле; отдельный агент должен проверить картинки на содержательные и визуальные ошибки.
- Не снижать глубину устройства структур и вывода асимптотики.
