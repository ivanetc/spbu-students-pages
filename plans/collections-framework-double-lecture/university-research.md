# Исследование университетских материалов по коллекциям

Дата доступа: 13 ноября 2026 года. Изучены четыре самостоятельных курса/набора материалов. Выбор продиктован совпадением уровня (начало Java или промежуточный курс после ООП) и наличием открытых учебных текстов, слайдов либо заданий. Это исследование структуры преподавания, а не источник нормативных утверждений о Java 21: API и детали OpenJDK 21 надо отдельно сверять с Javadoc и кодом JDK.

## 1. Cornell University — CS 2110, Object-Oriented Programming and Data Structures, Fall 2025

**Авторы/аудитория.** На [слайдах лекции 19](https://www.cs.cornell.edu/courses/cs2110/2025fa/lectures/lec19-slides.pdf) указаны Matt Eichhorn и Leah Perlmutter. [Программа курса](https://www.cs.cornell.edu/courses/cs2110/2025fa/) называет его промежуточным курсом программирования и проектирования ПО. Язык — Java; точная учебная версия JDK на прочитанных страницах не установлена.

**Прочитано:** [12. Collections and Generics](https://www.cs.cornell.edu/courses/cs2110/2025fa/lectures/lec12/), [13. Linked Data](https://www.cs.cornell.edu/courses/cs2110/2025fa/lectures/lec13/), [14. Iterating over Data Structures](https://www.cs.cornell.edu/courses/cs2110/2025fa/lectures/lec14/), [19. Sets and Maps — слайды](https://www.cs.cornell.edu/courses/cs2110/2025fa/lectures/lec19-slides.pdf), [20. Hashing](https://www.cs.cornell.edu/courses/cs2110/2025fa/lectures/lec20/), [Discussion 10: Reverse Indexing with Hashing](https://www.cs.cornell.edu/courses/cs2110/2025fa/discussions/dis10/). Текст лекции 19 по адресу `/lectures/lec19/` при чтении ответил тайм-аутом; содержание здесь не приписывается непрочитанной странице.

**Порядок и предпосылки.** До коллекций идут сложность, классы, интерфейсы, полиморфизм и generics. Затем отдельно: List как ADT и динамический массив → связные данные → итераторы → стеки и очереди → деревья → Set/Map → хеширование. Курс разводит эти темы по многим занятиям, поэтому его объём нельзя механически сжать до 160 минут.

**Приёмы объяснения и упражнения.** Сначала контракт `CS2110List`, затем представление через `storage` и `size`, инвариант `0 <= size <= capacity`, сдвиги при вставке и расширение массива. Амортизированную цену добавления выводят из редкости копирований. Связный список вводят как ответ на стоимость сдвигов, рисуют узлы и ссылки. В лекции об обходе вычисляют, что цикл с `get(i)` для связного списка даёт `O(n²)`, а итератор позволяет один линейный проход. Хеширование мотивируют прямой адресацией `boolean[10000]`, затем объясняют корзины, коллизии, коэффициент заполнения `n/c` и повторное распределение при росте. Ожидаемое `O(1)` привязано к допущению о равномерном распределении и ограниченному коэффициенту заполнения; увеличение таблицы стоит `O(n)` разово. Задание с обратным индексом меняет `Map<Course,List<Student>>` на `Map<Student,List<Course>>` и заставляет выбрать порядок обхода и устранить повторы.

**Пригодность.** Особенно полезны линия «контракт → представление → инвариант → стоимость» и отдельное доказательство, почему индексный обход `LinkedList` дорог. Для нашего курса нужно оставить одну компактную модель динамического массива и цепочки, а не вводить самодельные классы полностью. Университетский пример с обратным индексом хорошо сочетается с моделью студентов и групп.

## 2. UC Berkeley — CS 61B Data Structures, Fall 2024

**Авторы/аудитория.** [Курс](https://fa24.datastructur.es/) указывает преподавателей Justin Yokota и Peyrin Kao. Это бакалаврский курс структур данных на Java после вводного программирования. Версия Java на изученных страницах явно не зафиксирована.

**Прочитано:** [календарь и последовательность лекций](https://fa24.datastructur.es/), [Project 1A: LinkedListDeque61B](https://fa24.datastructur.es/projects/proj1a/), [Project 1B: ArrayDeque61B](https://fa24.datastructur.es/projects/proj1b/), [Lab 08: Hashmaps](https://fa24.datastructur.es/labs/lab08/). В календаре есть ссылки на главы и слайды про массивы и хеширование, но глава учебника про массивы во время обращения ответила тайм-аутом; выводы ниже опираются на открытые задания и календарь.

**Порядок и предпосылки.** Курс сначала разбирает ссылочные списки, двусвязные списки и массивы, затем задаёт две реализации `Deque` — на связных узлах и массиве. Хеширование идёт позже, после деревьев. Предпосылками задания выступают generics, интерфейсы, Java-ссылки и тестирование.

**Приёмы объяснения и упражнения.** Студент получает один контракт `Deque61B`, реализует его разными структурами и проверяет функциональное поведение тестами. Для связной версии требуется кольцевая двусвязная структура с фиктивным узлом; `addFirst/addLast/removeFirst/removeLast` обязаны выполняться без цикла и рекурсии, что делает доказательство `O(1)` проверяемым по коду. Для `get` прямо требуется обход. В массивной версии студенты моделируют кольцевые индексы и расширение; `get` здесь должен быть константным. В лабораторной `MyHashMap` задаются корзины, цепочки, `equals`, обновление значения старого ключа, коэффициент заполнения, рост и повторное распределение элементов. Простая анимация демонстрирует коллизии и resize.

**Пригодность.** Полезен учебный ход «один интерфейс — две реализации — разные гарантии стоимости» и упражнение, где студенты считают переходы по ссылкам. Полная реализация дека и карты слишком велика для одной сдвоенной лекции; можно использовать короткий фрагмент с `Node` и одну таблицу корзин.

## 3. MIT — 6.031 Software Construction, Spring 2021

**Авторы/аудитория.** [Архив курса](https://web.mit.edu/6.031/www/sp21/) указывает MIT EECS и весну 2021 года; [общая информация](https://web.mit.edu/6.031/www/sp21/general/) предполагает базовую беглость программирования. Материалы используют Java; в примерах документации упоминается Java 15, поэтому их нельзя принимать за перечень возможностей Java 21.

**Прочитано:** [Reading 1: Static Checking](https://web.mit.edu/6.031/www/sp21/classes/01-static-checking/), [Reading 2: Basic Java](https://web.mit.edu/6.031/www/sp21/classes/02-basic-java/), [Reading 19: Writing a Program with Abstract Data Types](https://web.mit.edu/6.031/www/sp21/classes/19-programming-with-adts/), [Reading 26: Map, Filter, Reduce](https://web.mit.edu/6.031/www/sp21/classes/26-map-filter-reduce/).

**Порядок и предпосылки.** Коллекции появляются очень рано, при переходе от Python к Java: массив фиксированной длины → `List<Integer>` / `ArrayList` → `Set` и `Map` → операции и generics. Реализацию структур данных этот материал почти не разбирает. В дальнейшем курс возвращается к ADT и их представлению, а map/filter/reduce идёт значительно позже.

**Приёмы объяснения и упражнения.** Сопоставляет знакомые Python list/set/dict с Java `List/Set/Map`; показывает `List` слева и `ArrayList` справа как различие интерфейса и реализации. Операции даны в короткой таблице, состояние иллюстрируется снимками объектов. `List.of`, `Set.of`, `Map.of` вводятся вместе с ограничением на изменение. Затем `for-each` используется для обычной обработки; позднее map/filter/reduce мотивируется повторяющимися циклами по последовательностям. В работе с ADT курс рекомендует сначала спецификацию и тесты, потом выбор представления и проверку инварианта.

**Пригодность.** Для первой половины нашей лекции подходит вопрос «какой тип выражает задачу?» и короткая таблица базовых операций. Преимущество — ясный переход для студентов с опытом Python. Внутреннее устройство придётся брать из других учебных источников. Для перехода к будущим лямбдам и Stream API полезен контраст между несколькими ручными циклами и одной цепочкой обработки, без преждевременного объяснения Stream.

## 4. Princeton University — COS 226 / Algorithms, материалы Robert Sedgewick и Kevin Wayne

**Авторы/аудитория.** [Слайды по стекам, очередям и массивам](https://algs4.cs.princeton.edu/lectures/keynote/13StacksAndQueues-2x2.pdf) и [слайды по хеш-таблицам](https://algs4.cs.princeton.edu/lectures/keynote/34HashTables-2x2.pdf) подписаны Robert Sedgewick и Kevin Wayne; это официальный учебный ресурс на домене Princeton. [Календарь COS 226 Fall 2025](https://www.cs.princeton.edu/courses/archive/fall25/cos226/lectures.php) показывает порядок аналогичных тем, но не доказывает, что именно эти архивные слайды были показаны осенью 2025 года. [Precept 6 Spring 2025](https://www.cs.princeton.edu/courses/archive/spring25/cos226/precepts/precept6.pdf) — отдельная прочитанная практика. Материалы на Java, но слайды старше Java 21 и не заменяют документацию современного JDK.

**Порядок и предпосылки.** Анализ алгоритмов → стеки/очереди на расширяемых массивах и связных списках → интерфейсы/итераторы → поиск по ключу → хеш-таблицы. Курс рассчитан на отдельный семестр по алгоритмам; предварительно нужна уверенность в базовом программировании.

**Приёмы объяснения и упражнения.** На раннем этапе ясно разводятся клиент, интерфейс и реализация. Хеширование объясняется через выбор индекса массива, проверку равенства и неизбежные коллизии. Сравниваются цепочки и открытая адресация, измеряются ожидаемые длины цепочек при гипотезе равномерного хеширования, отдельно показан худший сценарий. Таблица сопоставляет гарантии и средний случай для последовательного поиска, дерева и хеш-таблиц. В практикуме студент вручную размещает ключи в таблице с цепочками и линейным пробированием, затем сравнивает две функции хеширования строк.

**Пригодность.** Для нашей лекции особенно полезны явное разделение гарантии, ожидаемой цены и амортизированной цены, а также одно ручное упражнение с коллизией. Открытую адресацию можно упомянуть только как альтернативный дизайн: она не описывает `HashMap` в OpenJDK 21. Доказательства вероятностных оценок и сравнение всех схем поиска перегрузят 160 минут.

## Общие наблюдения и выводы для нашего курса

### Наблюдения из источников

1. Все четыре набора различают **операции/контракт** и **представление/реализацию** до таблиц сложностей. Cornell и Princeton делают это центральной осью; MIT и Berkeley демонстрируют на паре интерфейс–класс.
2. Cornell, Berkeley и Princeton разбивают динамические массивы, связные узлы, обход и хеширование на несколько занятий или заданий. Одно сдвоенное занятие требует более строгого отбора.
3. Стоимость операции объясняется конкретным действием структуры: доступ по индексу, сдвиг ссылок в массиве, проход по узлам, копирование при расширении, просмотр корзины. Оценка `O(1)` для хеширования не подаётся как безусловная гарантия.
4. Университетские упражнения заставляют студентов предсказать состояние после операций или число действий, а не только запомнить таблицу асимптотики.
5. MIT отделяет будущую функциональную обработку от первоначального знакомства с коллекциями; Cornell отдельно показывает причину существования `Iterator` через `O(n²)` индексного обхода связного списка.

### Редакторские выводы (инференция, не дословные требования источников)

- В нашей первой части дать один предметный вопрос на каждый контракт (`List`, `Set`, `Map`, `Queue/Deque`), показать дерево интерфейсов, гарантии порядка и 2–3 коротких клиентских фрагмента.
- Во второй части использовать две общие модели: **массив + размер/ёмкость** и **массив корзин + цепочки/деревья**. На каждой вывести цену операции из числа перемещений/просмотров; `HashSet` объяснить через `HashMap`, а не как четвёртую независимую структуру.
- Обязательно разобрать `Iterable`/`Iterator` хотя бы настолько, чтобы объяснить `for-each`, линейный обход `LinkedList` и безопасное удаление при обходе. Подробное написание собственного итератора оставить для чтения.
- Оставить место для мини-задачи на выбор коллекции и для ручной симуляции коллизии/resize. `ArrayDeque` дать как практическую реализацию `Deque`; полную реализацию кольцевого массива можно вынести в дополнительное чтение.
- Отмечать, где источник использует учебную реализацию, а где речь об OpenJDK. Например, формула `hash % capacity` хороша для вводной модели, но не является точным описанием индекса в `HashMap` OpenJDK 21.
