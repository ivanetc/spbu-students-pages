# Домашнее задание: Reliable Cashback Service

## Контекст

Вы разрабатываете небольшой backend-сервис для маркетплейса.

Когда пользователь совершает успешную покупку, система должна в итоге начислить пользователю кешбэк.

Система состоит из двух логических частей:

```text
Payment module
↓
Kafka event
↓
Cashback module
↓
Redis cashback balance
```

Модуль оплаты отвечает за обработку покупок.

Модуль кешбэка отвечает за начисление кешбэка.

Эти части системы должны взаимодействовать асинхронно через Kafka.

Баланс кешбэка должен храниться в Redis и читаться из Redis.

---

# Цель задания

Реализовать Spring Boot-приложение, которое:

- обрабатывает покупки;
- сохраняет покупки в PostgreSQL;
- публикует события о покупках в Kafka;
- асинхронно начисляет кешбэк на основе Kafka-событий;
- хранит текущий баланс кешбэка пользователя в Redis;
- возвращает баланс кешбэка из Redis;
- корректно работает при временной недоступности Kafka.

# Правила начисления кешбэка

Размер кешбэка:

```text
5% от суммы покупки
```

Примеры:

```text
1000 -> 50
2500 -> 125
999 -> 49
```

Используйте целочисленное деление.

---

# Функциональные требования

## 1. Создание покупки

Реализуйте endpoint:

```http
POST /payments
```

Тело запроса:

```json
{
  "userId": "user-1",
  "amount": 1000
}
```

### Требования

Endpoint должен:

- создавать успешную покупку;
- сохранять информацию о покупке в PostgreSQL;
- в итоге публиковать Kafka-событие о завершённой покупке;
- возвращать успешный ответ даже если Kafka временно недоступна;
- не начислять кешбэк синхронно внутри HTTP-запроса.

---

## Формат ответа

HTTP status:

```text
201 Created
```

Тело ответа:

```json
{
  "paymentId": "generated-id",
  "userId": "user-1",
  "amount": 1000,
  "status": "COMPLETED"
}
```

`paymentId` должен быть уникальным.

---

# 2. Kafka Event

Успешные покупки должны в итоге приводить к появлению Kafka-события в topic:

```text
purchase-events
```

Формат события:

```json
{
  "eventId": "unique-event-id",
  "paymentId": "payment-id",
  "userId": "user-1",
  "amount": 1000,
  "eventType": "PURCHASE_COMPLETED"
}
```

Требования:

- `eventId` должен быть уникальным;
- одна и та же покупка не должна приводить к повторному начислению кешбэка;
- события не должны теряться при временной недоступности Kafka.

---

# 3. Обработка кешбэка

Приложение должно асинхронно обрабатывать события о покупках из Kafka.

После обработки события приложение должно увеличить баланс кешбэка пользователя в Redis.

Пример:

```text
Покупка: userId=user-1, amount=1000
Кешбэк: 50
Redis balance после обработки: user-1 -> 50
```

Если у пользователя уже был кешбэк, новая сумма должна добавиться к текущему балансу.

Пример:

```text
Текущий баланс: 50
Новая покупка: 2000
Кешбэк за покупку: 100
Новый баланс: 150
```

---

# 4. Хранение баланса кешбэка

Текущий баланс кешбэка пользователя должен храниться в Redis.

Endpoint получения баланса кешбэка должен читать баланс из Redis.

Нельзя каждый раз пересчитывать баланс кешбэка из истории покупок в PostgreSQL.

PostgreSQL используется для хранения покупок и данных, необходимых для надёжной работы системы.

Redis используется как быстрое представление текущего баланса кешбэка.

---

# 5. Получение баланса кешбэка

Реализуйте endpoint:

```http
GET /users/{userId}/cashback
```

Пример ответа:

```json
{
  "userId": "user-1",
  "cashback": 50
}
```

Если у пользователя нет кешбэка:

```json
{
  "userId": "user-1",
  "cashback": 0
}
```

Требования:

- endpoint должен читать текущий баланс из Redis;
- если значения в Redis нет, нужно вернуть `0`;
- endpoint не должен пересчитывать баланс из PostgreSQL.

---

# Требование асинхронности

Кешбэк НЕ должен начисляться синхронно внутри `POST /payments`.

Следующий сценарий должен работать корректно:

```text
1. Пользователь создаёт покупку
2. HTTP-запрос успешно завершается
3. Сразу после запроса кешбэк может ещё отсутствовать
4. Через некоторое время кешбэк появляется после асинхронной обработки Kafka-события
```

---

# Требование надёжности

Система должна корректно переживать временную недоступность Kafka.

Следующий сценарий должен работать корректно:

```text
1. PostgreSQL и Redis доступны
2. Kafka временно недоступна
3. Пользователь создаёт успешную покупку
4. Покупка успешно сохраняется
5. Kafka становится доступна позже
6. Событие о покупке в итоге публикуется
7. Kafka consumer обрабатывает событие
8. Баланс кешбэка в Redis в итоге обновляется
```

Успешная покупка не должна теряться из-за временной недоступности Kafka.

---

# Требование идемпотентности

Кешбэк не должен начисляться несколько раз для одного и того же события покупки.

Если одно и то же Kafka-событие будет обработано повторно:

```text
кешбэк всё равно должен быть начислен только один раз
```

Пример:

```text
Событие PURCHASE_COMPLETED для payment-1 обработано дважды.
amount = 1000
cashback = 50

Итоговый баланс должен увеличиться на 50, а не на 100.
```

# Технические требования

## PostgreSQL

Используйте PostgreSQL для хранения покупок.

Минимально покупка должна содержать:

```text
paymentId
userId
amount
status
createdAt
```

Статус успешной покупки:

```text
COMPLETED
```

---

## Kafka

Используйте Kafka для асинхронного взаимодействия между обработкой покупок и начислением кешбэка.

Название topic:

```text
purchase-events
```

---

## Redis

Используйте Redis для хранения текущего баланса кешбэка пользователя.

Рекомендуемый формат ключа:

```text
cashback:{userId}
```

Пример:

```text
cashback:user-1 = 50
```

Можно выбрать другой формат ключей, если поведение системы соответствует требованиям.

---

# Правила валидации

## Некорректная сумма покупки

Суммы меньше или равные нулю должны отклоняться.

Пример:

```json
{
  "userId": "user-1",
  "amount": 0
}
```

Ожидаемый ответ:

```text
400 Bad Request
```

---

## Некорректный userId

Пустой `userId` должен отклоняться.

Пример:

```json
{
  "userId": "",
  "amount": 1000
}
```

Ожидаемый ответ:

```text
400 Bad Request
```
